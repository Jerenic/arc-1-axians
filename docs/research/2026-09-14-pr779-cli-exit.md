# PR #779: quality failures must reach the CLI exit code

## Root cause

Reviewed PR #779 at `f737e7f76e67963aa26b3544afe1cc04b2bb8837`.
`atc_ci` and `unittest_ci` return completed JSON reports with a boolean `fail`.
Quality failures correctly remain successful MCP calls, preserving structured
reports. The CLI's generic call route, however, only evaluates `isError` and
therefore exits zero for `fail:true`. `diagnoseCiQualityFailed` exists but has no
production caller. Its tests exercise a local ternary instead of CLI execution.

## Plan and review

1. Test `main(['call', 'SAPDiagnose', ...])` with dependency-injected tool outcomes,
   both CI actions, text/JSON rendering, passing/failing reports and tool errors.
   Assert returned process code and preserved report output together.
2. Wire the helper into the real generic CLI route, scoped to SAPDiagnose and
   the two new CI actions. Keep generic non-CI actions and dedicated existing CI
   commands unchanged. Render first so failure never discards reports.
3. Require a completed result with explicit boolean `fail:false` for these CI
   actions to pass. Missing/malformed/incomplete quality results must not turn
   the new route green. Preserve `evaluateResults:false` behavior: the producer
   explicitly sets `fail:false`, which remains authoritative.
4. Run CLI-focused tests and the repository gates. Review the final diff and add
   normal commits to the contributor's existing PR (maintainer edits enabled).

Plan review: no change to MCP `isError`, SAP calls, permissions, threshold logic,
or report formats. Exit 1 means tool/quality failure; usage still returns 2.
The stronger result validation is intentionally restricted to the new CI actions.
It prevents a damaged or incomplete report from being interpreted as success.

## Review iteration

The four new CLI regression cases failed on the PR's original behavior and passed
after integration. The full suite then exposed three pre-existing PR failures:
two schema-budget assertions still expected 74,000 bytes although the PR explicitly
sets 76,000; the maintained multi-target action table omitted the two new actions
already present in the PR's policy/schema. Synchronize those contracts without
changing runtime permissions or raising another budget. The measured full write
surface is 74,677 bytes (1,323 bytes below the existing PR ceiling); read-only and
per-tool ceilings remain unchanged. This existing PR budget increase remains
visible for the maintainer's review.

## Final verification

After the review iteration: 6,616 unit tests across 215 files passed. Typecheck,
Biome, policy validation, build, and file/schema budgets passed using dependencies
installed from this PR's own lockfile. Runtime regressions exercise actual `main`
argument parsing/dispatch/rendering for both CI actions and both output modes,
including tool errors, empty/malformed/incomplete reports and ordinary actions.
Reports remain available on nonzero exits. No live SAP CI execution was required
to establish this CLI defect; communication-arrangement availability and the
broader new backend remain separate deployment/PR validation concerns.
